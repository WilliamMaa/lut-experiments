# 19 — 分布式邻居推理节点：LUT 作为可取回的内容寻址计算资产

> 矩阵总纲见 14 号，总结论见 16 号，LUT × 矩阵交叉分析见 18 号。
> 本文回答一个新方向：**v6 LUT + v8 serving 能不能扩展成"节点互
> 补的推理网络"**——每个节点持有部分 KV / LUT / 权重，缺什么向
> 邻居取，计算可委托。结论：方向成立，但立论有一处必须修正，
> 实验路径要按工程量重排。

## 0. 愿景与一句话评估

愿景：一组能互相补足的小型推理节点，**状态可取（KV）、资产可
缓存（LUT）、计算可委托（远端执行）**，中心只负责模型发布与节
点引导，正常推理在邻居间完成。

评估：**值得做，"从邻居取 LUT 后本地查表"是第一篇能出的结果；
"远端执行 dense"是拿前几路的数算完 break-even 再决定建不建的
第二篇。** 提案的原始立论有一处事实性错误，修正后三条资源线
各管一个稀缺维度，才构成统一协调的坐标系。

已有外部件（不重复造）：LMCache P2P 支持节点间直接读 KV
（仍需 coordinator 做发现）；Petals 证明"节点只持部分 blocks
协作推理"形态可运行（不代表通信便宜）；Mooncake Transfer
Engine 提供 P2P 传输 handshake。本研究的增量不在传输层，在
**需求仲裁**。

## 1. 必须修正的立论：LUT 省算力，不省容量

实测（v8 audit + bundle，L37/38/39）：

| 项 | 每层体积 |
|---|---|
| LUT（coarse 16384×2048 + resid 32×65536×64，fp16） | ≈ **320 MB HBM** |
| 它替代的 dense shared_expert 权重（fp16） | ≈ **150 MB 量级** |

**LUT 是它替代权重的约 2 倍大。** 它拿容量换 FFN 的 MAC 归零。
因此"LUT 降低节点对完整权重的依赖"是反的：

- LUT 降低的是节点的**算力依赖**（FFN matmul → O(1) 查表）；
- 容量维度 LUT 必输（320 vs 150 MB）。

正确的节点剧本：**算力弱的节点用 LUT 扛 FFN 重活**（容量不值
钱、算力稀缺），而不是"用 LUT 腾地方少存权重"。这条修正决定
实验里每条比较路径的账怎么算。

## 2. 用真实数字算 break-even

activation 传输量 = tokens × 2048 × 2 B（bf16）：

| 场景 | 每层每前向传输 |
|---|---|
| 64k prefill 一次前向 | ≈ **256 MB** —— 已达 LUT 体积的 0.8× |
| decode 每 token | 4 KB，但每层每 token 一次 RPC 串行依赖 |

推出两条硬结论：

1. **"取 LUT → 本地复用"几乎稳赢。** 表是静态资产，取一次
   320 MB；remote-exec 每请求都要搬 256 MB（64k）。第二次长
   上下文请求起 LUT 路径开始赚。且与矩阵行 1-3 不冲突：
   **KV 复用吃共享前缀，LUT 覆盖非共享后缀的 FFN**——互补。
2. **remote-exec 只在 prefill 有戏，且先过 KV 复用这关。**
   64k 请求里可被邻居 KV 覆盖的前缀部分（矩阵已证 token 级
   一致）不算 remote-exec 的功劳；只有非共享后缀才是它的
   用武之地，要和"PIT 聚合 + KV 取块"比成本，不是和朴素
   重算比。**decode 远程化直接排除**（串行 RPC 延迟杀
   throughput），不浪费实验格子。

## 3. 实验路径（按 build cost 重排）

| # | 路径 | 新增工程量 | 状态 |
|---|---|---|---|
| 1 | A 本地 dense | — | 已有（acc 0.9844） |
| 2 | A 本地 LUT | — | 已有（acc 0.9551，三层） |
| 3 | **A 从 B 取 LUT → 本地查表** | 很小：一次性 320 MB 传输 + 插件加载，E2 testbed 两 worker 间即可测 | **第一步** |
| 4 | A 发 activation → B 远端执行 dense | 大：vLLM forward 内嵌 RPC、序列化、prefill 分块；与 0.70 mem-util serve 配置相争 | 拿 1-3 的数算 break-even，过线再建 |

路径 3 的实验设计（E2 testbed，沿用 11 号 runbook 纪律）：

- 两 worker 固定邻居配置，不做发现协议（隔离变量）。
- A 无 LUT，B 持有；请求到达 A 后首次触发跨节点取表（计时、
  计字节），之后全部本地。
- 判读指标（过程计数器优先）：首取延迟、累计网络字节 vs
  累计替代 MAC 数、复用 N 次后的均摊成本交叉点。
- 对照 1/2 路已知质量差（0.955 vs 0.984），路径 3 质量应与
  路径 2 逐位一致（同一张表）——**质量不是本实验变量，成本
  才是**。

路径 4 的立项判据（先算后建）：

\[
\text{remote-exec 划算} \iff
\frac{\text{非共享后缀 token 数} \times \text{FFN 每 token 代价}}
{\text{activation 字节} + \text{RPC 延迟摊销}}
>
\text{KV 取块 + PIT 路径的同一比值}
\]

左边的分子用路径 1/2 的实测延迟差估出 FFN 每 token 代价；
右边是矩阵行 1-3/7 已量出的 regime。算不过就不建。

## 4. 与矩阵的关系：第四类资源、E3 的推广

矩阵消三类重复（16 号 §6）：跨位置复用、跨层级保留、并发聚合。
本文是 E3（fetch-cost ratio，14 号 §3 实验表）的资源集合扩展：
E3 问"KV 块取回代价多少时 placement 开始划算"，这里问
**"LUT 资产取回 vs 远端计算 vs 本地权重"三选一何时各划算**。

18 号交点 B 的叙事在此落地为机制：**LUT 表是第一个"按需取回的
内容寻址计算资产"**——名字 = (模型版本, 层号, ckpt 哈希)，
任何节点取回后内容一致，天然满足矩阵行 1/8 的判定，无 freshness
问题。邻居网络是它的天然场景：A 训好的表，B 用时取，一次传输
替代 B 侧永久驻留 320 MB。

不提供的证据（纪律同 18 号 §2）：LUT 跨节点复制不是矩阵行 5
的 replication 证据（静态资产无驱逐外部性）；表分发不是行 3
证据。

## 5. 执行顺序（不变）

1. **v9 等价性 → 三层重训**：扩层前置，节点能 shed 多少算力
   取决于 LUT 覆盖多少层。
2. **路径 3 实验**：现有 3 层 bundle 就够测机制，不挡 v9。
3. **路径 4 break-even 计算**：有 1-3 的数就算，过线才建。
4. 全部失败也不亏：路径 3 若量出"复用 2 次即赚"的交叉点，
   本身就是 LUT 部署形态的定量结论（静态资产按需下发 vs
   预装）。

## 6. 一句话 contribution（如果走通）

> named inference state 之上再加一层 named computation
> asset：LUT 表按内容命名、跨节点一致取回，使"算力受限节点"
> 无需完整权重即可完成 FFN 推理；其价值 ∝ 复用次数 × FFN
> 每 token 代价 − 一次性取表成本，由复用 regime 定量界定。
