# LLM-LUT v1.1 结果分析 + v1.2 方向判断

## v1.1 核心数据

| Mode | KL | PPL | Acc | Recovery |
|------|-----|-----|-----|----------|
| zero | 3.4989 | 2337 | 0.198 | 0% |
| v1.0_bucket_2d | **0.6066** | **41.94** | **0.488** | **82.66%** |
| codebook_soft | 0.6629 | 43.34 | 0.445 | 81.05% |
| codebook_hard | 0.8259 | 45.74 | 0.471 | 76.40% |

**结论：Learned Codebook 没有 beat Fixed Uniform Binning。**

---

## 为什么 v1.1 失败了？

### 1. Centroid 坍缩（Coverage 暴跌）

| Epoch | Coverage | Temperature | Entropy |
|-------|----------|-------------|---------|
| 1 | 96.88% | 0.97 | 3.96 |
| 10 | 81.25% | 0.69 | 3.37 |
| 20 | 48.44% | 0.36 | 2.99 |
| 30 | 64.06% | 0.10 | 3.06 |
| 40 | 70.31% | 0.05 | 3.45 |
| 60 | 68.75% | 0.05 | 3.49 |

Coverage 从 97% 暴跌到 68%，说明 **K-means init 后 centroids 在训练中没有稳定**，大量 centroids 被"抛弃"。

原因：`temperature` 从 1.0 一路降到 `min_temperature=0.05`，soft assignment 迅速变尖锐。当 temperature 很低时，usage regularization（KL divergence to uniform）的梯度几乎无法推动 centroids 回到均匀分布。

### 2. Soft-to-Hard Gap 巨大

- Soft assignment: KL = 0.66
- Hard assignment: KL = 0.83
- **Gap = 0.17**（25% 相对差距）

这意味着：即使 soft assignment 接近 v1.0 bucket，一旦切换到推理时的 hard assignment，效果就大幅下降。Codebook 学到的 centroids 边界不够 clean。

### 3. Local MSE 没有转化为 Model-Level KL 优势

训练 history 显示 MSE 从 1.04 降到 0.84，但 model-level KL 没有相应改善。这说明 codebook 的 local 近似误差虽然减小了，但没有打在"正确的地方"——uniform grid 的固定边界恰好能更好地对齐 activation 到 target 的映射关系。

## v1.1 的核心教训

> **Uniform binning 的 grid 结构可能比任意的 K 个 centroid 更适合 LLM activation space。**

Grid 结构保证了：
- 每个 cell 覆盖一个规则的 address 区域
- 没有"空洞"（coverage = 100% by construction）
- 推理时 hard assignment 没有 soft-to-hard gap

K-means centroids 的问题：
- 容易在数据密集区过度集中
- 低密度区出现空洞
- Hard assignment 时最近邻误差被放大

---

## v1.2 的解读

v1.2 SUGGESTIONS 的核心思路是 **可分解性假设**：

> 2D bucket 的优势是否来自两个 address 的独立可加贡献？如果是，可以用两个 1D LUT 替代一个 2D LUT，大幅节省参数。

### v1.2 实验设计

| 实验 | 公式 | 参数量 | 目的 |
|------|------|--------|------|
| A | `LUT1[a1] + LUT2[a2] + b` | ~8KB | 纯 additive，从头训练 |
| B | ANOVA init → fine-tune | ~8KB | joint bucket 的可分解距离 |
| C | A + `LUTc[8×8]` interaction | ~12KB | 折中方案：可加主体 + 小交互项 |

### v1.2 的价值判断

**从研究叙事角度**：
- 如果 A/B 接近 2D bucket → 说明 group 4 的规律是**可分解的**，两个 head 独立贡献
- 如果 A/B 差很多 → 说明存在**强二阶交互**，必须用 2D 结构
- 这个诊断本身就有价值，能告诉我们 address 设计的本质

**从工程角度**：
- 如果 C 能达到 2D bucket 的 90% 效果，但参数量只有 5%（12KB vs 256KB），那 C 是最实用的方案
- 即使 A/B 不够好，C 也可能是一个好的 trade-off

### v1.2 的风险

- **Additive 假设可能不成立**：如果 2D bucket 的优势主要来自 interaction，那 A/B 都会显著差于 bucket
- **Local MSE 的天花板**：和 v1.0/v1.1 一样，如果 fixed 2D bucket 已经是 strong baseline，trainable additive 可能也没有太多空间

## 综合判断

| 方向 | v1.0 | v1.1 | v1.2 |
|------|------|------|------|
| Fixed binning | ✅ 82.7% recovery | — | — |
| Trainable table | ≈ bucket (+0.03%) | ❌ 差 6pt | ? |
| Learned codebook | — | ❌ 差 6pt | — |
| Additive decomposition | — | — | **待验证** |

**结论**：
1. v1.0 的 2D bucket 是目前最强 baseline（recovery 82.7%）
2. v1.1 证明 learned codebook 无法超越 fixed grid
3. v1.2 的 additive decomposition 是下一个合理的尝试，特别是实验 C（可加主体 + 小交互项），它有参数效率优势
4. 如果 v1.2 C 也不理想，说明这个 address space 的 2D 结构中有**强不可分解的 interaction**，fixed 2D bucket 已经是近似最优

---

## 建议

**做 v1.2，但只做 B + C**：

- **B（ANOVA init + fine-tune）**：诊断性实验，回答"joint bucket 离可加分解有多远"
- **C（Additive + 8×8 interaction）**：工程性实验，看看能否用 1/20 参数达到类似效果

不做 A（从头训练 additive），因为 B 的 ANOVA init 已经是 additive 的最强起点，如果 B 都不够好，A 只会更差。
