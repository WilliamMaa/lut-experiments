# Fashion-MNIST 动态注入实验小结

## 背景

之前 MNIST 上验证了 LUT（O(1) 查表）动态注入有效（两阶段 LUT-3 做到 95.84%，端到端 MLP 版本 97.31%）。现在换到 Fashion-MNIST，验证方法在更复杂数据上的泛化性。

目标不变：**存算一体设备上的 O(1) 动态参数注入**，不是刷准确率。

---

## 我们试了啥

| 方案 | 注入位置 | 动态机制 | 测试集 | 增益 |
|------|----------|----------|--------|------|
| 基线 | — | 无 | 86.58% | — |
| LUT-3 原版 | 输出层 | 20-dim 乘性权重 | 87.72% | +1.14% |
| LUT-3 v2 | 输出层 | 40-dim 乘加 + 大表 + 尺度加权 | 87.83% | +1.25% |
| **LUT-3 main** | **backbone_main** | **340-dim 替换 weight+bias** | **88.12%** | **+1.54%** |
| VQ-LUT | 输出层 | 64 码本离散选择 | 86.43% | **-0.54%** |

> MLP 生成版本（非 LUT）也跑了，87.82%，和 LUT-3 main 差不多，但计算不是 O(1)，已放弃。

---

## 核心结论

1. **注入位置决定一切**
   - 输出层乘性/乘加：~+0.7~1.2%
   - 替换 backbone_main(16→20) 的 weight+bias：**+1.54%**
   - **规律**：动态参数越靠近特征层，leverage 越大。

2. **LUT 查表 ≈ MLP 生成（在效果上）**
   - backbone_main 注入：LUT 88.12% vs MLP 87.82%
   - 说明 O(1) 查表在效果上不输前馈生成，验证了硬件友好路线的可行性。

3. **基线天花板是硬约束**
   - 16-dim bottleneck 的全连接网络，无论怎么注入，上限就是 **~88%**。
   - 动态注入是"锦上添花"，backbone 的表达能力决定了天花板。

4. **VQ 离散化在复杂数据上失效**
   - 64 个码本强制聚类，结果比基线还差（-0.54%）。
   - Fashion-MNIST 类内方差太大，per-cluster 粒度太粗，丢失了关键个性化信息。
   - MNIST 上 VQ 可能有效（同类几乎一样），但 Fashion-MNIST 上不行。

---

## 当前的主要瓶颈

| 瓶颈 | 说明 |
|------|------|
| backbone 信息瓶颈 | 16-dim 对 Fashion-MNIST 太弱，但扩大 backbone 偏离微型网络预设 |
| LUT 存储随维度线性爆炸 | 340-dim 注入 → 114K 表 + 141K query_proj = **~255K 总参数** |
| query_proj 是隐藏大头 | 输出 1020-dim 坐标的 query_proj 比 LUT 表本身还大 |
| 过拟合 | 即使 LUT 查表，训练-测试差距仍有 3-5% |

---

## 下一步方向（建议）

### 方向 1：压缩 query_proj（优先级高）

当前 query_proj 输出 1020-dim（340×3），参数量 141K，是存储大头。

可行思路：
- 减少 LUT 尺度数（3→2 或 1），query_proj 输出维度直接减半
- query_proj 后接轻量分解，比如输出低维坐标再用小 MLP 映射到高维坐标（但需权衡是否破坏 O(1)）
- 尝试让多个维度共享 query 坐标，而非每个维度独立查询

**目标**：把 LUT-3 main 的总存储从 255K 压到 50K 以内，同时保住 87.5~88% 的准确率。

### 方向 2：换数据集验证边界（优先级中）

Fashion-MNIST 可能太极端（类内方差过大）。换一个"中等复杂度"的数据集，比如：
- **EMNIST Letters**：结构比 MNIST 复杂，但比 Fashion-MNIST 规整
- **Kuzushiji-MNIST**：日文手写，类内有一定变化

如果 LUT 在中等复杂度数据上能稳定带来 **2~3% 增益**，说明方法有价值，只是 Fashion-MNIST 太极端。

### 方向 3：混合粒度（优先级中，偏探索）

VQ 离散化太粗（64 个码本），LUT 连续查表太细（per-sample）。试试混合：

- **类别级别粗粒度**：10 个类别各维护一组基础动态参数（10×340 = 3.4K）
- **LUT 细粒度残差**：在类别参数基础上，LUT 查表输出一个小的残差修正

`final_param = class_base_param[class_id] + lut_residual(query)`

这样既有稳定性（类别基础参数），又有个性化（LUT 残差）。

### 方向 4：扩大 backbone（优先级低，偏离核心目标）

如果把 backbone 从 784→16→20 扩到 784→64→128→20，基线本身就能到 90%+，LUT 的绝对增益空间也会变大。但这偏离了"微型网络 + 动态注入"的初衷，更像"大模型 + 锦上添花"。

---

## 一句话总结

> LUT 查表动态注入在 Fashion-MNIST 上有效但有限（+1.54%），注入位置比查表策略更重要；VQ 离散化在复杂数据上完全不行。下一步最该做的是**压缩 query_proj 降低存储开销**，以及**换中等复杂度数据集验证方法边界**。
