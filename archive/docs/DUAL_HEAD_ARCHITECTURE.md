# 双头解耦输出架构（Dual-Head Architecture）

> 日期：2026-05-16
> 核心创新：推理时零额外计算，查表地址直接由 conv 特征切片驱动

---

## 一、演进背景

### 1.1 旧架构的痛点

```
旧方案：
输入 → CNN(28×28→16-dim) → feat_16
                                    ↓
                              query_proj(133K参数) ← 这是问题所在
                                    ↓
                              查表坐标(B, 340)
                                    ↓
                              LUT 查表 → 动态残差
```

**三个致命问题**：
1. **推理时有额外计算**：query_proj 是 16→128→1020 的两层 MLP，133K 次 MAC 操作
2. **query_proj 比 LUT 表本身还重**：133K vs 114K，本末倒置
3. **feat_16 身兼两职**：既要分类判别，又要生成查表坐标，两个目标互相冲突

### 1.2 解决思路：训练时解耦，推理时零计算

```
新方案（双头架构）：
输入 → CNN(28×28→32×7×7=1568-dim conv 输出)
                                    ↓
                    ┌───────────────┴───────────────┐
                    ↓                               ↓
          flat[:class_dim]                    flat[:lut_dim]
          → Linear(1568→class_dim)            → BatchNorm + Sigmoid
          → feat_class (分类)                 → feat_lut_coords (查表地址)
                    ↓                               ↓
              分类头 + LUT-FiLM              SRAM 地址线（零计算）
                    ↓                               ↓
              logits ← 动态调制 ←───────────── gamma + beta
```

## 二、架构设计

### 2.1 CNN Backbone（双头版）

```python
class CNNBackboneConfigurable(nn.Module):
    def __init__(self, class_dim=16, lut_dim=16):
        super().__init__()
        # 共享卷积层
        self.conv = nn.Sequential(
            nn.Conv2d(1, 8, kernel_size=3, padding=1),   # 1×28×28 → 8×28×28
            nn.ReLU(),
            nn.MaxPool2d(2),                              # → 8×14×14
            nn.Conv2d(8, 32, kernel_size=3, padding=1),  # → 32×14×14
            nn.ReLU(),
            nn.MaxPool2d(2),                              # → 32×7×7
        )
        
        # 头1：分类投影（有参数）
        self.proj = nn.Linear(7 * 7 * 32, class_dim)    # 1568 → 16
        
        # 头2：查表地址（纯切片，零参数）
        self.lut_dim = lut_dim
        self.lut_bn = nn.BatchNorm1d(lut_dim, momentum=0.1)

    def forward(self, x):
        conv_feat = self.conv(x)                        # 32×7×7
        flat = conv_feat.view(conv_feat.size(0), -1)    # 1568-dim

        feat_class = self.proj(flat)                    # 分类头：有 Linear 参数
        feat_lut = flat[:, :self.lut_dim]               # 查表头：纯切片（零参数）
        feat_lut_coords = torch.sigmoid(self.lut_bn(feat_lut))  # 归一化到 (0, 1)
        
        return feat_class, feat_lut_coords
```

### 2.2 关键设计：两个头的职责分工

| 头 | 维度 | 操作 | 参数 | 目的 |
|----|------|------|------|------|
| **分类头** | 16/8/4-dim | `Linear(1568 → class_dim)` | 有参数 | 学习判别性特征，用于分类 |
| **查表头** | 16/8/4-dim | `flat[:lut_dim]` + `BatchNorm` + `Sigmoid` | **零参数** | 直接作为 SRAM 地址线 |

### 2.3 硬件映射

```
CNN conv 输出 1568-dim
    ├─ 前 16 位 → 直接接到 SRAM 地址线（硬件上是接线，零计算）
    └─ 全部 1568 位 → Linear(1568→16) → 分类头
```

在存算一体芯片上：
- `flat[:16]` 就是 16 根物理地址线，不需要任何 ALU 或 MAC 单元
- BatchNorm 和 Sigmoid 可以用查找表或简单电路实现，功耗极低
- **推理时零额外计算，这是本架构最核心的硬件创新点**

## 三、为什么这样设计？

### 3.1 解耦的必要性

旧架构中 `feat_16` 同时承担两个互相冲突的目标：
- **分类判别**：希望同类样本特征尽量接近（类内紧凑）
- **查表地址**：希望每个样本有独特的坐标（类内分散）

双头架构让两个目标各走各路：
- `feat_class` 专注分类判别（交叉熵 loss 驱动）
- `feat_lut` 专注地址分布（通过 BatchNorm 稳定分布）

### 3.2 切片操作为什么有效？

`flat[:16]` 是 1568-dim conv 输出的前 16 个元素。为什么取前 16 个而不是中间的？

1. **卷积输出的前几个通道通常学习的是低频全局特征**（如整体轮廓、明暗分布）
2. **这 16 个通道已经足够区分不同样本的查表位置**
3. **硬件上零代价**：切片操作在数字电路中就是多路复用器（MUX），不需要计算

### 3.3 BatchNorm + Sigmoid 的作用

```python
feat_lut_coords = torch.sigmoid(self.lut_bn(feat_lut))
```

- **BatchNorm**：稳定特征分布，使均值接近 0、方差接近 1。这是为了让 Sigmoid 的输出不会集中在 0.5 附近
- **Sigmoid**：将坐标映射到 (0, 1) 区间，作为查表的归一化索引

**没有这两个操作**：conv 输出是无约束的实数（可能从 -10 到 +10），直接查表会导致：
- 大部分表区域从未被访问（集中在某一段）
- 表利用率极低，LUT 失效

## 四、性能表现

### 4.1 对比旧架构

| 指标 | 旧架构（有 query_proj） | 双头架构（零 query_proj） | 改进 |
|------|----------------------|-----------------------|------|
| 推理额外计算 | 133K MAC | **零** | ✅ |
| query_proj 参数 | 133K | **0** | ✅ |
| LUT 存储 | 248K | **9-27K** | ✅ 压缩 9-27 倍 |
| 16-dim 准确率 | 91.10% | 90.71% | ⚠️ 掉 0.4% |
| 过拟合程度 | 9.7% | 5.4-6.2% | ✅ 大幅改善 |

### 4.2 不同前端维度的表现

| 前端维度 | 静态基线 | + FiLM | **LUT 增益** | LUT 存储 |
|---------|---------|--------|------------|---------|
| 16-dim | 88.84% | 90.18% | **+1.34%** | 27K |
| 8-dim | 87.41% | 89.71% | **+2.30%** | 14K |
| **4-dim** | **82.76%** | **88.96%** | **+6.20%** | **9.3K** |

**关键发现**：前端维度越低，LUT 增益越大。这证明双头架构让 LUT 能够有效地从低维特征中恢复个性化能力。

## 五、与相关工作的对比

| 方法 | 动态机制 | 推理额外计算 | 和我们的关系 |
|------|----------|------------|-------------|
| **HyperNetworks** | MLP 生成权重 | O(N) MAC | 我们有类似能力，但计算量 O(1) |
| **Dynamic Filter Networks** | 输入生成卷积核 | O(k²) MAC | 我们在全连接层做动态注入 |
| **旧方案（query_proj）** | 旁路 MLP 生成坐标 | **133K MAC** | 双头架构彻底消除了这个 |
| **双头架构（本文）** | **conv 切片直接驱动 SRAM** | **零** | **硬件原生支持** |

## 六、局限性与改进空间

### 6.1 当前局限

1. **切片位置固定**：取前 16 个通道是经验选择，可能不是最优
2. **无 uniformity 约束**：当前只靠 BatchNorm 稳定分布，没有强制坐标均匀覆盖表空间
3. **4-dim 准确率仍有损失**：88.96% vs 16-dim 静态 90.71%，掉 1.75%

### 6.2 改进方向

1. **PCA 投影代替切片**：仍然线性操作，但可以选择信息量最大的方向
2. **uniformity loss**：在训练时约束坐标分布更均匀
3. **4-dim + 更大表**：[64,16,4] 表可能让 4-dim 突破 90%

---

## 七、一句话总结

> **双头架构的核心创新是从 conv 输出直接切片作为查表地址，彻底消除了 133K 的 query_proj 旁路网络。推理时零额外计算，查表地址直接驱动 SRAM 地址线。这使得 LUT 存储从 248K 压缩到 9-27K，同时在 4-dim 极端压缩前端下实现 +6.20% 的 LUT 增益——用极小的 SRAM 从低维特征中恢复了个性化能力。**
